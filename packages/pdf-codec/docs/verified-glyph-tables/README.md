# Verified glyph tables

How the tables `src/verified-glyph-tables.ts` reads are verified (the data is in `src/verified-glyph-tables-advent.ts` and `src/verified-glyph-tables-truetype.ts`): one table per verified font subset, keyed by the SHA-256 of the decoded font program. A glyph sheet is a rendering of a subset with one cell per glyph, showing the glyph as the embedded font program draws it, its glyph name in the font program and the Unicode character the table reads it as (`unmapped` where it is left as it was). Sheets are generated, so they are not committed (a `.gitignore` in this directory ignores `*.png`): the sheet for a table is attached to the pull request that adds the table, as an image in the description or a comment, and is regenerated from the font program, found by the SHA-256 in the table, when a reviewer needs it.

A table is added only for a subset whose glyphs were rendered from the embedded program and checked against the symbol they stand for, so a reviewer can re-check a table by comparing its cells on the attached or regenerated sheet to the shapes. A glyph whose symbol could not be settled from its outline is left unmapped. A table lists glyphs by the program's own glyph name, because these producers share one program between many font dictionaries that assign its glyphs to different codes; the name a dictionary's `/Differences` gives a code selects the glyph.

Both families of subset are the ones a textbook typeset with the Advent 3B2 system embeds: a symbol font laid out like TeX's math symbol font (`AdvMT_SY`, `AdvP4C4E74`), a math italic font (`AdvMT_MI`, `AdvP4C4E51`), a delimiter and large-operator font laid out like TeX's extension font (`AdvP4C4E46`) and a roman font with Greek capitals (`AdvP4C4E59`). A one-glyph subset that names its glyph through `/Encoding /WinAnsiEncoding` instead of `/Differences` (the f483 table) is read by the name that base encoding gives its code, and a subset whose font dictionaries carry no `/Encoding` at all (the 78448 table, whose program's built-in encoding is StandardEncoding) by the name the program's own encoding gives it. The producer writes each glyph's name and `/ToUnicode` entry as if the name were what the glyph draws, so an equals sign is `/onequarter`, a left parenthesis is `/eth` and a size-3 left parenthesis is `/C16`.

In `AdvP4C4E46` a size variant of a delimiter is read as the character it enlarges (every `(` size as `(`), the corners of an assembled bracket as the Unicode bracket corners, and the large sum, integral, intersection and conjunction as their Unicode n-ary operators. The pieces a tall brace, radical or bracket is assembled from other than the bracket corners, and the short bar `/ffi`, are left unmapped: a piece has no character of its own that the outline alone can settle.

A CFF subset converted from a TrueType Symbol face (`Symbol092`, in an SEL conference paper, Western Protective Relay Conference 2001, "Advanced Application Guidelines for Ground Fault Protection") names each glyph `G` followed by the glyph's id in the TrueType face and carries no `/ToUnicode`, so no glyph list reads the names and the core-face glyph orders (`core-font-glyph-orders.ts`) do not cover Symbol. The blank `/G32` is read as a space (the subset sets it between a bullet and the text it introduces), the paren pieces as the Unicode parenthesis pieces the Symbol font's own `parenlefttp` and the like resolve to, and `/G65`, whose outline is a capital A, as the Latin letter rather than Alpha, since the paper sets it as the ampere unit (`( 1 or 5 A )`).

A second SEL conference paper ("Review of Ground Fault Protection Methods for Grounded, Ungrounded, and Compensated Distribution Systems") embeds another `Symbol092` subset of the same kind, read the same way plus the Greek letters, comparison operators, the arrow, the dot operator and the bracket pieces it uses (`/G106`, the loop-form phi, as U+03C6, and `/G162`, the bare bar of the arrow extension, as U+23D0 like the other bare extension bars), an `MT.Extra091.688` subset with the same numbering, and one subset per equation of the kind a printer driver makes from a TrueType symbol face (`TT12FCo00` and the like), which names each glyph `G` followed by the glyph's character code in hexadecimal. In those, `/Ge6` to `/Gfb` are the parenthesis and square-bracket pieces at the codes the Symbol encoding gives them, read as U+239B to U+23A6, and `/G72` (`/G114` in the `MT.Extra` subset) and `/G76` (`/G118`) are the full arrow and the upper-barbed harpoon an equation sets over a phasor, read as U+2192 and U+21C0. A subset is keyed by its own program, so each of these one- to twelve-glyph subsets has its own table.

## Adding a subset

1. Take the decoded font program (`/FontFile3` for a Type 1C font) and the glyph names the font dictionaries' `/Differences` arrays assign, and hash the program with SHA-256.
2. Render every glyph those names select from the program's own CharStrings onto a sheet: one cell per glyph with its name and the character it is read as, headed by the program's SHA-256.
3. Name the character each glyph draws, from the shape alone, and list only the glyphs whose symbol is not in doubt.
4. Add the table to `ADVENT_SOURCES` or `TRUETYPE_SOURCES`, whichever kind of subset it is, and attach the sheet to the pull request as an image in its description or a comment. Never commit the sheet.
